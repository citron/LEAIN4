# Chapitre 20 — Capstone : une recette d'entraînement, prouvée

:::tip[TL;DR]
**En bref.** Tout le cours est une boucle vue sous vingt angles : initialiser, forward, perte, gradient, cliper, pas, décroître le taux, mesurer. Ce chapitre soude les théorèmes du kit du Chapitre 5 en **une seule recette** — weight decay découplé + clipping de gradient + schedule exponentiel — et la prouve sur la quadratique de référence : dans la boîte de clipping la recette est **invisible** (`recipe_step_eq : décroissance d'abord + clipping = SGD L2 ordinaire) ; la recette itérée a la **forme fermée** $(1 - \eta(2+w))^t w_0$ (`recipe_closed`) ; sous la condition de stabilité $0 \le \eta(2+w) \le 2$ le carré de la perte **ne croît jamais, à aucun itéré** (`recipe_iter_sq_le`) ; et le schedule dépense un **budget total fini** $\eta_0/(1-\gamma)$ (`recipe_budget`). La démo lance la même recette en `Float` sur de vrais pixels MNIST : **90,0 % de précision test en 3 époques**, pendant que chaque instance `Rat` imprimée au-dessus décide `true`.

**Mots nouveaux, en simple :**

- **Recette** : la séquence fixe — décroître les poids, clipper le gradient, faire le pas, réduire le taux — que implémentent les cases de tout entraîneur moderne.
- **Pas invisible** : quand le gradient est petit (dans la boîte), la recette compliquée calcule exactement le pas SGD ordinaire avec L2 : la machinerie ne mord que sur les pics.
- **Contraction** : chaque pas multiplie le poids par un seul facteur $c = 1 - \eta(2+w)$ ; le compteur d'époques devient un exposant, et la preuve tient en une ligne géométrique.
- **Budget** : un taux décroissant ne peut jamais déplacer les poids de plus de $\eta_0/(1-\gamma)$ au total, quel que soit le nombre d'époques ajoutées.
:::

Les chapitres 1–19 ont construit les pièces. Un capstone n'est pas une architecture de plus — c'est **la boucle elle-même**, certifiée : chaque case d'un entraîneur moderne (weight decay, clipping, schedule) est un théorème ici, et leur composition est une chaîne de preuves `Rat`. Puis les mêmes définitions, exécutées en `Float`, apprennent MNIST.

La chute de `recipe_step_eq` : pour **SGD ordinaire, le decay découplé est un mensonge que l'on se raconte** — appliquer la décroissance au poids puis marcher sur le gradient clipé calcule bit pour bit le pas L2 régularisé. Le découplage ne mérite son nom que sous Adam (exercice 4 du kit du Chapitre 5), où le gradient est normalisé et les deux règles divergent vraiment.

## La boucle, certifiée à chaque époque

```lean file=Ch20/Capstone.lean#loop
```

`recipe_iter_sq_le` est toute la boucle vue comme système dynamique : sous une condition de stabilité douce sur le produit « taux × courbure », aucun itéré de la recette complète — décroissance, clipping, pas — n'augmente le carré de la perte. Pas « en moyenne », pas « à la limite » : à l'époque $t$, pour tout poids de départ, exactement. La chaîne de preuve tient en une ligne de théorie du cours : le pas est une multiplication par $c \in [-1,1]$, donc $c^2 \le 1$ (`sq_le_one` du Chapitre 5), donc $c^{2t} \le 1$ (`powN_le_one`), donc $w_t^2 = c^{2t} w_0^2 \le w_0^2$.

## L'exécuter : la face exacte et MNIST

`lake exe capstone` imprime les deux faces. La face exacte évalue les théorèmes sur $w_0 = 2$, $\eta = 1/20$, $w = 1/50$ :

```text
  t = 0: w = 2          closed form = 2                       w^2 <= w0^2: true
  t = 1: w = 899/500    closed form = 899/500                 w^2 <= w0^2: true
  t = 2: w = 808201/500000  closed form = 808201/500000       w^2 <= w0^2: true
  ...
  clipped gradient at w = 3: clip 5 6 = 5
  schedule budget (10 epochs): spent 6513215599/10000000000 <= bound 1: true
```

La face `Float` lance les mêmes définitions — `decay` sur chaque poids, `clamp` sur chaque coordonnée du gradient, schedule `lrAt` — sur de vrais MNIST avec le réseau du Chapitre 5 :

```text
MNIST face: train 4000, test 2000
  epoch 1: lr = 0.050000, test accuracy = 0.833000
  epoch 2: lr = 0.035000, test accuracy = 0.895000
  epoch 3: lr = 0.024500, test accuracy = 0.900000
```

Lisez les deux faces ensemble — et gardez-les distinctes : les théorèmes vivent sur une quadratique **scalaire** $L(w) = w^2$ à taux constant (la boîte de clipping inactif de `recipe_step_eq`, la contraction géométrique de `recipe_iter_sq_le`, le budget de schedule de `recipe_budget` pris séparément). Le parcours MNIST est un MLP **vectoriel** avec un schedule variable, un clipping actif sur de vrais gradients, et une perte non convexe. Les preuves scalaires ne certifient pas cette expérience, et le budget de schedule seul ne dit rien sur la perte du MLP : le parcours est un *compagnon exécutable* de la recette — mêmes définitions, arithmétique `Float`, graine documentée dans le code — pas l'instance numérique du théorème. Ce qui se transfère est la conception de la boucle, pas la garantie. Ce que montre le parcours à 90 % sur une seule graine est une démonstration, pas une évaluation statistique (le relancer sur plusieurs graines et rapporter moyenne et dispersion est un bon exercice).
