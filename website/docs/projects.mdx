# Integrative projects

Three end-to-end projects. Each reuses the course's Lean abstractions, ships a runnable skeleton, and grades **proved guarantees** separately from **empirical targets** — a passing grade never mixes the two.

Grading grid, common to the three projects:

| Component | Weight | Evidence required |
|---|---|---|
| Runs reproducibly | 20 % | exact command, seed, `data/` preparation, output log |
| Proved properties | 30 % | Lean declarations that compile; each with a one-line statement of its hypotheses |
| Empirical targets | 30 % | metric, baseline, split, seeds (≥ 3 seeds for comparative claims; mean ± spread) |
| Report honesty | 20 % | every claim labelled with its status (proved / hypothesis / numeric test / observed / out of scope) |

## Project 1 — MNIST pipeline, end to end

**Spec.** Load MNIST (`scripts/get-mnist.sh`), build an MLP with `LeanDL.Core` tensors, train with the Ch05 kit (SGD + the Ch20 recipe), evaluate on the official test split, and prove at least three local properties of your own pipeline (e.g. softmax is a distribution, the loss is non-negative, one SGD step on the quadratic never increases loss).

**Deliverables.** `Demos/Project1.lean` (target `project1`), a `data` preparation section, seed fixed and printed, train/test split sizes stated, per-epoch loss and final test accuracy.

**Success criteria.** Compiles with the repo's toolchain; run finishes < 5 min; test accuracy ≥ 90 % at the documented seed (regression, not a claim of generalization); ≥ 3 added proofs with zero `sorry` outside exercises; report separates the scalar proofs from the vector run (the Ch20 boundary).

**Evaluation.** Empirical target = documented accuracy at ≥ 3 seeds; proved = your added lemmas; the MLP's generalization is explicitly out of scope.

## Project 2 — Mini-GPT

**Spec.** Minimal byte-level tokenizer over a corpus generated locally (e.g. a few hundred lines of deterministic text committed to the repo); a stack of `N` causal Transformer blocks built from the Ch09 block with the no-leak property preserved by induction; next-token cross-entropy from the Ch16 toolkit; greedy generation.

**Deliverables.** `Demos/Project2.lean` (target `project2`), a stackNoLeak-style inductive proof that the stack of `N` blocks never reads the future, a printed sample of generated bytes, logits and per-step loss visible.

**Success criteria.** stackNoLeak_N compiles (the induction over block count is the graded proof); loss decreases across the documented run at the fixed seed; generated text shows local structure (report must not claim linguistic quality); KV caching documented as extension, not simulated.

**Evaluation.** Proved = structural no-leak induction; empirical = loss curve and sample quality with explicit limitations; a real GPT's capabilities are out of scope.

## Project 3 — Representation learning

**Spec.** Two encoders over a small labeled toy dataset (e.g. rotated MNIST digits): contrastive training with the Ch17 InfoNCE loss, a CLIP-style symmetric variant (Ch19) with one encoder per view; analyse collapse using the Ch15 collapse theorem as the reference case.

**Deliverables.** `Demos/Project3.lean` (target `project3`), a linear-probe evaluation (logistic regression on frozen embeddings, trained deterministically), InfoNCE loss curve, a collapsed control run (constant encoder) proving the probe detects collapse.

**Success criteria.** InfoNCE ≥ log(n+1) floor observed on the batch statistic (ties to the proved floor); linear-probe accuracy on the control run ≈ chance, on the trained run clearly above; loss curve printed with seed; report states that the Ch15 theorem covers the toy collapse objective, not your encoders.

**Evaluation.** Proved = reuse of course theorems with correct hypothesis citation; empirical = probe accuracy across ≥ 3 seeds (mean ± spread); transfer to real vision-language models is out of scope.

## Rules common to all projects

1. No Mathlib, no external libraries, no Python: Lean 4.35.0 and the course core only.
2. Every number you report names its seed and its command.
3. A claim without a proof must not use the word "proved"; a single seed must not be presented as an evaluation.
4. Cite the source paper for every architecture you implement (the per-chapter References sections list the primaries).
