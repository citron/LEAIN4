# Chapter 6 — Convolutional networks

:::tip[TL;DR]
**In short.** A convolution reuses one small pattern detector at every position of an image. We prove that convolution is linear and shift-equivariant, then train a CNN that reaches 97 % on MNIST.

**New words, in simple terms:**

- **Convolution**: Slide a small pattern detector over the input and record how well it matches at each position.
- **Kernel (filter)**: The small grid of weights used by a convolution.
- **Weight sharing**: Using the same weights at every position, so the network needs far fewer parameters.
- **Translation equivariance**: Shift the input and the output shifts the same way: a pattern is found wherever it is.
- **Channel (feature map)**: One output image produced by one kernel.
- **Max-pooling**: Shrink an image by keeping only the biggest number of every small block.
- **CNN**: Convolutional neural network: convolutions, non-linearities and pooling, followed by a classifier.
:::


A dense layer on a $28\times 28$ image has $784$ weights *per neuron*, and has no idea that two neighbouring pixels are neighbours. A **convolutional layer** builds in two assumptions about images:

- **Locality**: an output looks only at a small window of the input.
- **Weight sharing**: the same small set of weights (the **kernel**) is applied at every position.

<Figure src="conv.svg" alt="A kernel of length 3 sliding along an input of length 7" caption="Each output is a dot product of the kernel with one window of the input." />

## One-dimensional convolution, with the shapes in the type

We start in one dimension, where the proofs are short. A kernel of length $k+1$ slides over an input of length $m+k$ and produces exactly $m$ outputs. In Lean this arithmetic is part of the type, so a kernel that does not fit simply does not type-check.

```lean file=Ch06/Conv.lean#conv1d
```

(Deep learning calls this *convolution*; strictly it is cross-correlation, because the kernel is not flipped. The distinction does not matter for learning.)

:::tip[Lean Corner: proofs inside terms]
The index `x ⟨i + j, _⟩` needs a proof that `i + j < m + k`. We supply it with `by omega`, using the bounds `i < m` and `j < k + 1` that come from the `Fin` types. Lean checks it at compile time, so there are no out-of-bounds reads at run time.
:::

## What we can prove

**1. Convolution is linear**, in the input and in the kernel. A convolutional layer is therefore a *linear map with a special structure*, followed by a non-linearity.

```lean file=Ch06/Conv.lean#conv_linear
```

**2. Convolution is translation-equivariant**: shifting the input by one position shifts the output by one position. This is exactly what weight sharing buys: a pattern is detected wherever it occurs.

```lean file=Ch06/Conv.lean#equivariance
```

**3. The gradient with respect to the kernel is a correlation.** Suppose $s$ is the gradient arriving from the next layer. The loss contribution is $\ell(\mathrm{ker}) = \sum_i s_i\,(\mathrm{ker}\star x)_i$. Exchanging the two sums, which is the only real work and needs a lemma about double sums (`vsum_comm`), gives $\ell(\mathrm{ker}) = \sum_j \mathrm{ker}_j\cdot\mathrm{corr}(s,x)_j$. A linear form $\sum_j \mathrm{ker}_j\,g_j$ has gradient $g$, so $\partial\ell/\partial \mathrm{ker}_j = \mathrm{corr}(s,x)_j$:

```lean file=Ch06/Conv.lean#corr
```

So the backward pass of a convolution is again a convolution-like operation: you do not need a new idea to train it.

## A CNN for MNIST

Now two dimensions. Our network: a $3\times 3$ convolution with 4 channels ($26\times 26$ outputs), ReLU, $2\times 2$ **max-pooling** (keep the largest of every $2\times2$ block, giving $13\times 13$), a dense layer to 10 logits, softmax cross-entropy.

```mermaid
flowchart LR
  I["image 28x28"] --> C["convolution 3x3, 4 kernels"] --> R["ReLU"] --> P["max-pooling 2x2"] --> F["dense layer"] --> S["softmax: 10 digits"]
```

*The CNN of this chapter, from pixels to a digit.*


```lean file=Ch06/Cnn.lean#net
```

Backpropagation, by stages:

1. The output layer's error is `p - onehot y`, as in Chapter 5.
2. Max-pooling sends the gradient to the single position that won the maximum; the other three positions get zero.
3. ReLU lets the gradient through only where the unit was active.
4. The kernel gradient is the correlation of the input with that gradient: the two-dimensional version of theorem 3.

```lean file=Ch06/Cnn.lean#backward
```

### The flat loop *is* the convolution

The network above stores images and kernels in flat arrays: the kernel sits in `K[c*9 + a*3 + b]`, the image in `x[i*28 + j]`, and each conv cell is a hand-written double loop. Is that layout the mathematics of the first half of this chapter, or only shaped like it? It is, and the bridge is proved over exact $\mathbb{Q}$:

```lean file=Ch06/Conv.lean#cnn_row
```

Feed the 28-wide image row to the 3-tap kernel row and `conv1d` produces exactly the 26 output columns — the type-checker enforces the shape ($28 - 3 + 1 = 26$), and `cnn_row` shows the cell at column `j` equals the net's loop term for term. Summing the three kernel rows, `cnn_cell_rows` identifies the net's full double loop with three formal `conv1d` applications. This is the same round-trip shape as Chapter 9's `concat_head`/`head_concat` for multi-head attention.

:::warning What is proved here, and what is not
Theorems 1–3 and the row bridge above are about the one-dimensional layer. The two-dimensional code above is a direct generalisation: one conv cell is proved equal to the flat loop, the pooling and dense stages are *not* proved. We check them numerically instead: the demo compares the kernel gradient with a central finite difference of the loss.
:::

## Run it

```bash
cd lean
lake exe cnn 60000 10000 3
```

```text
kernel gradient check: max |backprop - finite difference| = 0.000000
epoch 1: test accuracy = 0.963400
epoch 2: test accuracy = 0.955100
epoch 3: test accuracy = 0.970600
```

The gradient check agrees to better than $10^{-6}$ (the printed value rounds to 0). With only **4 channels and 3 passes of plain SGD** the network reaches **97.1 %** on the 10 000 test images, in under three minutes on a laptop CPU. The dip at epoch 2 is ordinary SGD noise with a constant learning rate; this is one run with one seed, not a benchmark. Compare with the 96.4 % of the one-hidden-layer network in Chapter 5, which has far more weights.
